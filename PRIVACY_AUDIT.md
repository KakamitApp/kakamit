# Privacy Audit Notes

## Summary

Kakamit is designed so that user-entered health tracking data stays on the
user's device.

## Data Flow

1. User enters a DGBS or stool entry in the UI.
2. Entry is stored in local Preact state (`src/lib/entries.tsx`).
3. Entry is persisted to IndexedDB via `src/lib/db.ts`.
4. Reports and insights are computed locally (`src/lib/report.ts`,
   `src/workers/insights-worker.ts`).
5. Export creates a local JSON/CSV file in the browser.
6. Import reads a local JSON/CSV file selected by the user.

## Storage

### IndexedDB

Used for:

- DGBS entries
- Stool entries
- Comments
- Timestamps

Database:

- Name: `kakamit-db`
- Store: `entries` (keyPath `id`, index `timestamp`)

### localStorage

Used for:

- Language preference
- Theme preference

No health entries are stored in localStorage.

## Network Surface

The application has no backend API for user data.

Expected network activity:

- Static app assets
- PWA service worker assets
- Public static pages/assets

No expected network activity:

- No analytics
- No telemetry
- No crash reporting
- No ad networks
- No account system
- No cloud sync

## Export / Import

Export:

- JSON export is generated locally.
- CSV export is generated locally.
- Files are downloaded by the browser.

Import:

- User selects a local JSON or CSV file.
- Input is validated client-side.
- Invalid rows are skipped.
- Valid rows are written to IndexedDB.

## Service Worker

The service worker is generated by `vite-plugin-pwa`.

Purpose:

- Offline support
- Static asset precaching

The service worker must not transmit user data.

## Dependencies

Runtime dependency:

- `preact`

Build dependencies are listed in `package.json`.

Audit commands:

```bash
npm ci
npm audit
npm run build
```

## Known Caveats

- FODMAP/FAQ static templates may reference external Google Fonts unless
  self-hosted or removed.
- Firebase hosting config (`firebase.json`) may exist for deployment, but the
  app itself has no Firebase SDK or Firebase data access.
